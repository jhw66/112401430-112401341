# 拾光｜校园失物招领

基于第一次结对作业的“拾光”原型实现的 PC 网页版。围绕“发布信息 → 浏览或搜索 → 查看详情与联系方式 → 发布者更新状态”的主流程，不依赖框架、构建工具或服务器。

## 快速运行

1. 下载并解压整个项目文件夹，保持 `index.html`、`css/` 和 `js/` 的相对位置不变。
2. 用 Google Chrome 打开 `index.html`。无需运行 `npm install`，也无需启动服务器。
3. 在首页点击示例卡片查看详情；示例联系方式使用 `example.edu`，不是真实联系人。
4. 想测试完整流程时，先到“发布信息”填写一条自己的记录，再到“我的发布”把它标记为“已找到”或“已归还”。

本项目不要求网络连接。浏览器应允许此本地页面使用 `localStorage`；如浏览器阻止本地存储，页面会显示提醒，记录只能在本次打开期间保留。

## 功能与操作

| 功能 | 操作入口 | 行为 |
|---|---|---|
| 浏览寻物/招领 | 首页、发现信息 | 显示名称、地点、日期、类型和状态 |
| 搜索与筛选 | 首页搜索框、发现信息 | 匹配名称、类别、地点、描述；可组合类型、类别、状态筛选 |
| 查看详情与联系 | 点击信息卡片 | 查看完整描述、地点、时间；进行中的信息显示联系方式及复制按钮 |
| 发布寻物/招领 | 发布信息 | 校验必填字段、日期和联系邮箱，发布后展示成功页 |
| 更新状态 | 我的发布、本人发布的信息详情 | 寻物改为“已找到”，招领改为“已归还”；结束后隐藏联系方式 |
| 撤销结束 | 我的发布、本人信息详情 | 误点结束后恢复为进行中，重新显示联系方式 |
| 发布草稿 | 发布信息 | 自动保存填写内容，离开或刷新后恢复；发布成功后清除草稿 |
| 保留查找条件 | 搜索结果 → 详情 → 返回信息列表 | 保留关键词、类型、类别和状态筛选 |

示例信息用于方便测试浏览与搜索，不能在“我的发布”修改。只有在当前浏览器发布的记录能在该浏览器的“我的发布”中修改状态。额外提供了组合筛选、复制联系方式、自动草稿和撤销结束。原有记录的存储键保持不变，升级时继续读取旧记录；首次发现异常记录后，会在下次保存前备份原缓存。

## JavaScript 维护入口

- 修改字段规则：查看 `js/core/validation.js`；记录创建和状态变更在 `js/core/records.js`。
- 修改搜索、排序和统计：查看 `js/core/queries.js`；URL 参数和详情返回在 `js/app/router.js`。
- 修改本地保存和草稿：查看 `js/app/store.js`；原有存储键与损坏缓存备份机制继续保留。
- 修改页面内容：进入 `js/pages/` 中对应的页面文件；卡片、标签和表单控件共用 `js/app/ui.js`。
- 修改交互：查看 `js/app/events.js`；应用组装和首次渲染在 `js/app.js`。

浏览器通过 `index.html` 中的普通 `defer` 脚本按依赖顺序加载，继续支持直接双击打开 HTML，无需构建工具。新增模块时，要把脚本放在依赖模块之后、使用模块之前。业务模块也支持 CommonJS，Node.js 仍可通过 `require("./js/core.js")` 使用统一接口。页面烟雾测试读取 HTML 中的真实脚本清单，验证浏览器模块导出与加载顺序。

## 运行测试

安装 Node.js 18 或更新版本后，在项目目录执行：

```powershell
node --test tests/core.test.js tests/app-smoke.test.js
```

测试使用 Node.js 自带的 `node:test` 和 `assert`，没有第三方依赖；目前有 45 个自动化用例（27 个核心逻辑测试、18 个页面烟雾测试）。采用边界值与分支测试，覆盖必填字段、日期、邮箱、长度、非法类型、所有权检查、状态更新与撤销、缓存损坏及备份、搜索返回、草稿恢复、HTML 转义和重复提交。页面烟雾测试运行在模拟 DOM 中；另已在内置浏览器中实际走查主流程、复制按钮及窄屏布局。测试文件可在本地保留；按作业说明，上传仓库时并非必须包含它们。

## 建议的 Chrome 人工走查

1. 首页打开“蓝色校园卡”，确认详情中有地点、描述和示例联系方式。
2. 搜索“校园卡”，确认出现匹配结果；搜索不存在的词，确认空状态清楚。
3. 选择“招领”、类别“证件卡片”和“进行中”，确认组合筛选有效。
4. 发布一条新信息；缺少名称或描述过短时应出现错误提示，补齐后进入成功页。
5. 在“我的发布”打开该信息并更新状态；返回发现信息可筛选“已结束”，详情不再显示联系方式。
6. 刷新页面，确认本地记录和状态仍在；再用窄屏检查布局。
7. 在详情或“我的发布”点击“撤销结束”，确认恢复进行中及联系方式，再刷新核对。
8. 发布页填写部分字段后返回首页，再进入发布页或刷新，确认草稿恢复；发布成功后再进入发布页应为空表单。
9. 搜索并组合筛选后查看详情，使用“返回信息列表”，确认关键词和筛选条件保持不变。

## 数据范围与限制

为了满足“下载文件后直接用 Chrome 打开 HTML”的作业运行方式，使用浏览器 `localStorage` 保存本机发布的信息，未实现服务器数据库。不同设备或浏览器之间不会同步，`我的发布` 也只是基于本机记录的演示，不构成真正的身份认证或所有权证明。因此此版本适合课程功能演示，不能宣称已经提供校园范围的多人共享服务。若后续部署给真实用户，需要补充服务端存储、账号授权和联系方式保护。

2026-09-30 已通过 45 项自动化测试，并在内置浏览器、本地 HTTP 地址实际检查发布、草稿恢复、搜索筛选返回、复制联系方式、状态结束与撤销、刷新持久化，以及 320/390/650 像素宽度。课程要求的 Google Chrome 直接打开 `index.html` 仍需按上表核对；内置浏览器测试不计作该项验收。具体结果和截图见 `QA_2026-09-30.md`。此次交付只包含本地程序。
