# 拾光｜校园失物招领

拾光是一个面向校园场景的失物招领课程项目，基于原生 HTML、CSS 和 JavaScript 实现。围绕“发布线索 → 浏览与搜索 → 查看详情并联系 → 更新状态”的流程，提供寻物和招领信息的本机演示。

当前维护电脑浏览器界面，使用顶部导航和桌面布局；窗口缩小时提供紧凑桌面样式。应用没有第三方运行依赖，无需安装 npm 包或构建即可打开。

## 快速开始

1. 下载并解压完整项目，保留 `index.html`、`css/` 和 `js/` 的相对位置。
2. 用 Google Chrome 打开项目根目录的 `index.html`。
3. 在首页浏览示例信息，或进入“发现信息”搜索、筛选。
4. 在“发布信息”填写一条自己的寻物或招领记录。
5. 在“我的发布”查看记录，找回或归还物品后更新状态。

浏览器应允许页面访问 `localStorage`，以便刷新或再次打开后恢复记录与草稿。若存储受限，应用会显示提示，数据可能只保留在本次页面运行期间。

示例联系方式使用 `example.edu` 邮箱，仅用于演示。

## 功能说明

| 功能 | 入口 | 当前行为 |
| --- | --- | --- |
| 首页展示 | 首页 | 显示信息统计、仍在进行的最新线索和使用流程。 |
| 浏览全部信息 | 发现信息 | 展示本机记录与示例记录，按发布时间倒序排列。 |
| 通用关键词搜索 | 首页、发现信息 | 匹配物品名称、类别、地点和描述；联系方式不参与搜索。 |
| 独立地点筛选 | 发现信息 | 只匹配遗失／拾取地点，可与其他条件共同使用。 |
| 组合筛选 | 发现信息 | 同时使用关键词、地点、信息类型、物品类别和状态。 |
| 查看详情 | 信息卡片 | 展示物品属性、详细描述、发布时间和联系方式。 |
| 复制联系方式 | 进行中的信息详情 | 优先使用剪贴板 API，失败后尝试兼容复制；仍失败时提示手动复制。 |
| 发布信息 | 发布信息 | 校验必填项、日期和邮箱，发布后进入成功页。 |
| 自动保存草稿 | 发布信息 | 输入或选择字段时保存，离开或重新打开后恢复；发布成功后清除。 |
| 结束与撤销结束 | 我的发布、本机信息详情 | 寻物结束为“已找到”，招领结束为“已归还”；撤销后恢复进行中。 |
| 保留搜索条件 | 搜索结果 → 详情 → 返回 | 保留全部五项筛选；直接打开搜索链接或刷新也能恢复条件。 |
| 存储异常处理 | 全局提示 | 跳过非法缓存记录，保存前备份原损坏缓存，提示读写失败。 |

示例记录用于演示，不能修改状态。“我的发布”只展示当前浏览器保存的本机记录。已结束的信息仍保留，但详情隐藏联系方式；撤销结束后重新显示。

## 搜索与地点筛选

发现信息页面支持以下五项条件，填写的条件必须同时满足：

| 条件 | 参数名 | 匹配范围 |
| --- | --- | --- |
| 通用关键词 | `keyword` | 名称、类别、地点、描述。 |
| 地点关键词 | `place` | 仅匹配记录的 `place` 字段。 |
| 信息类型 | `type` | 全部、寻物、招领。 |
| 物品类别 | `category` | 全部或指定类别。 |
| 信息状态 | `status` | 全部、进行中、已结束。 |

例如，填写地点“图书馆”时，只有遗失／拾取地点包含“图书馆”的记录会命中；名称或描述中提到图书馆的其他地点记录不会因此命中。

关键词和地点采用包含匹配，会清理空白并忽略英文大小写。空白地点不增加筛选条件；相同发布时间的记录按编号排序。选择下拉框会读取当前表单，包括尚未单独提交的地点；点击“清除筛选”会清空所有条件。

搜索状态保存在 Hash 路由中，例如：

```text
#/search?place=图书馆&type=found&status=open
```

通过搜索结果打开详情后，详情链接携带返回入口，返回信息列表时恢复原条件。

## 发布规则

当前支持七类物品：证件卡片、钥匙、数码物品、雨具、水杯、书本文具、其他。

| 字段 | 校验规则 |
| --- | --- |
| 信息类型 | 必须选择寻物或招领。 |
| 物品名称 | 清理空白后为 2–40 个字符。 |
| 物品类别 | 必须属于支持的类别。 |
| 遗失／拾取地点 | 清理空白后为 2–60 个字符。 |
| 遗失／拾取日期 | 必须是有效日历日期，且不晚于浏览器本地日期。 |
| 物品描述 | 清理空白后为 10–500 个字符，保留换行。 |
| 联系邮箱 | 必须符合邮箱格式，且不超过 100 个字符。 |

校验失败时会显示字段错误并定位首个错误项；填写内容继续作为草稿保留。草稿允许未完成内容，正式发布时才执行完整校验。

## 技术与模块结构

| 层次 | 实现 | 职责 |
| --- | --- | --- |
| 页面入口 | HTML | 全局导航、内容容器、样式与脚本引用。 |
| 样式 | 原生 CSS | 基础、公共组件、各功能页面和电脑窗口适配。 |
| 业务逻辑 | `js/core/` | 字段校验、记录处理、缓存解析、查询和统计。 |
| 应用逻辑 | `js/app/` | 状态、存储、路由、公共界面工具和事件连接。 |
| 页面渲染 | `js/pages/` | 六个页面的 HTML 生成。 |
| 自动化测试 | Node.js `node:test`、`assert`、`vm` | 业务单元测试与模拟浏览器交互测试。 |

浏览器按 `index.html` 中的依赖顺序加载 19 个普通 `defer` 脚本：业务模块 → `core.js` → 应用工具 → 页面工厂 → 事件模块 → `app.js`。

`js/core.js` 汇总统一业务接口，同时支持浏览器和 Node.js CommonJS。`js/app.js` 组装状态、路由、界面工具与页面，绑定事件并完成首次渲染。CSS 通过 `css/styles.css` 统一导入，`desktop.css` 最后加载覆盖规则。

## 本地数据与异常处理

发布记录和草稿使用浏览器 `localStorage`：

| 存储键 | 用途 |
| --- | --- |
| `shiguang_local_posts_v1` | 本机发布的记录及其状态。 |
| `shiguang_publish_draft_v1` | 未完成的发布草稿。 |
| `shiguang_local_posts_v1_recovery_<时间戳>` | 发现异常记录后，在下一次保存前备份原缓存。 |

启动时，记录解析器剔除非法记录、重复编号和冒用演示编号的记录。旧版已保存的非邮箱联系方式仍可读取，但新发布信息必须填写有效邮箱。

若存储读写失败，应用提示当前状态，尽量继续使用内存中的记录和草稿。清理浏览器站点数据或更换设备、浏览器后，不保证恢复原有记录。

## 运行测试

运行应用不需要 Node.js。执行自动化测试需要 Node.js 18 或更新版本，无需安装第三方测试依赖。

在项目根目录执行全部测试：

```powershell
node --test tests/core.test.js tests/app-smoke.test.js
```

按范围运行：

```powershell
# 核心业务
node --test tests/core.test.js

# 页面交互
node --test tests/app-smoke.test.js

# 单个功能
node --test tests/core/queries.cases.js
node --test tests/app/search.cases.js
```

测试分为 **35 项业务测试和 33 项页面交互测试，共 68 项**。两个 `.test.js` 入口加载各功能 `.cases.js` 文件；公共数据和模拟浏览器工具位于 `tests/helpers/`。新增用例模块时，需要在对应入口添加 `require`。

业务测试覆盖校验边界、记录创建、所有权、状态更新、缓存解析、搜索、地点筛选、排序和统计。页面测试按 `index.html` 的实际脚本清单加载代码，覆盖提交、草稿、URL 条件恢复、详情返回、结束与撤销、存储异常和 HTML 转义。

## 当前范围

本项目是课程用的本机演示，没有服务端数据库、账号系统或跨设备同步。“本机发布”基于当前浏览器中的记录标记，不构成真实身份认证。

联系方式在进行中的详情页公开展示；发布时仅填写愿意公开的邮箱。示例数据与本机数据不会自动成为校园范围的共享信息。

当前仅维护电脑端界面。若后续扩展为多人共享服务，需要另行实现服务端存储、身份认证、授权和联系方式保护。
